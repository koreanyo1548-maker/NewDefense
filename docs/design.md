# 마왕성의 마지막 포탑 — 기획 원칙 적용 문서

> 조작은 가볍게, 선택은 풍부하게.
> 규칙은 적게, 조합과 상황은 다양하게.
> 운은 선택지를 흔들고, 전략은 그 운을 다룬다.
> 선택의 결과는 즉시 화면을 바꾸고, 그 변화가 다시 다음 선택의 욕망을 만든다.
> 성장해도 판단은 사라지지 않고, 매 판은 다음 가능성을 넓힌다.

## 게임 구조 (원칙 11)

| 질문 | 답 |
|---|---|
| 플레이어가 원하는 것 | "이번 판엔 이런 괴물 포대가 만들어졌다" |
| 이번 판의 목표 | 10웨이브 + 보스 버섯왕 방어 |
| 방해 요소 | 특성(장갑·떼거리·질주·보호막)을 가진 적. 런마다 조합이 다르게 섞임 |
| 판단 | 카드 3택1 · 소울로 리롤할지 모아둘지 · 엘리트 도전 여부 · 저주 수락 여부 · 집중 포격 타이밍/위치 |
| 실패 시 잃는 것 | 이번 런 빌드. 소울은 60%만 보관 |
| 성공 시 얻는 것 | 소울 100% 보관 → 보관소에서 새 선택지 해금 |
| 다시 하는 이유 | 해금한 키워드·시작 조건으로 다른 빌드를 만들어보고 싶어서 |

## 핵심 규칙 (원칙 6·7) — 플레이어가 배울 것은 이게 전부

**키워드 7종**(`js/data.js` `KEYWORDS`)

| 형태 | 효과 | 속성 | 효과 |
|---|---|---|---|
| 다중 | 투사체 수 +1 | 화염 | 지속 피해 |
| 관통 | 적을 꿰뚫고 계속 비행 | 냉기 | 둔화 |
| 연쇄 | 근처 적에게 튕김 | 치명 | 확률 2배 피해, 장갑 무시 |
| 폭발 | 범위 피해 | | |

- 규칙 하나: **키워드는 그 키워드를 가진 공격원의 모든 공격에 적용된다.** (포탑의 집중 포격도 포탑 공격이므로 포함)
- ★3 = 진화: 효과가 한 단계 더 퍼진다 (투사체 +2, 무한 관통, 2갈래 연쇄, 2차 폭발, 불/냉기 전파, 치명 3배).
- 영웅은 각자 고유 키워드 1개로 시작한다. 영웅별 예외 규칙은 없다.

**적 특성 4종**(`TRAITS`) — 각각 한 줄 규칙, 유리한 키워드는 있지만 정답은 하나가 아님

| 특성 | 규칙 | 유리한 대응 |
|---|---|---|
| 장갑 | 치명타가 아닌 피해 절반 | 치명 · 높은 화력 |
| 떼거리 | 작고 약하지만 3마리씩 | 다중 · 폭발 · 연쇄 |
| 질주 | 이동 속도 1.75배 | 냉기 · 집중 포격 |
| 보호막 | 첫 타격 무효 | 다중 · 연쇄 · 관통 |

새 적을 추가할 때 상호작용 규칙은 한 줄만 늘어난다 → 복잡도 예산 보존.

## 원칙별 구현 위치

| 원칙 | 구현 |
|---|---|
| ② 지루한 조작 자동화 | 포탑 완전 자동 사격. 탭 = 집중 포격(재충전 8초) — 언제·어디에 쓸지만 판단 |
| ③ 가벼운 선택, 큰 풀 | 카드 = 대상(포탑/영웅 6) × 키워드 7 + 영입·단련·포신·장전·재건·저주. 절반은 보유 키워드(★강화) 제시 |
| ④ 운 → 판단 | 리롤(소울 15, +10씩) · 엘리트 도전(3·6·8웨이브 후) · 저주 카드(Lv3+) |
| ⑤⑧ 결과가 화면에 | 다중=부채꼴, 관통=긴 궤적, 연쇄=번개선, 폭발=링, 화염/냉기=발광 궤적, 포신 강화=포탄·수정 크기, 영웅 단련=몸집·오라, 발밑 키워드 핍, 진화 시 대형 링·흔들림 |
| ⑦ 판 읽기 | 웨이브 특성 칩(HUD), 카드 화면의 "다음 웨이브" 미리보기, 클리어 토스트 예고 |
| ⑨ 화면 갱신 | 1–3 잡몹 → 4 엘리트 → 5 미니보스+보상 → 지역 변화(황혼/그믐/붉은 달) → 9 혼합 → 10 보스 |
| ⑩ 가능성 확장 메타 | 보관소: 관통·연쇄 키워드, 선발 영웅, 엘리트 사냥꾼, 시작 조건(외로운 포대·저주받은 성). 영구 스탯 상승 없음 |
| ⑫ 제작 가능성 | 신규 원화 0장. 틴트·크기·코드 도형(링/번개/보호막/속도선)·기존 아이콘만 사용 |

## 파일 구조

```
index.html        마크업만
css/style.css     스타일 (UI 표면은 assets/ui/*.webp 래스터)
js/data.js        모든 콘텐츠 테이블 + TUNING (콘텐츠 추가는 여기서)
js/game.js        엔진 (명중 규칙은 onHit/dealHit 한 곳)
assets/img        전투 스프라이트·배경
assets/ui         UI 아이콘·프레임
assets/fonts      TurretUI(Noto Sans KR 서브셋) + OFL 라이선스
assets/unused     현재 쓰지 않는 원본 아트(보관용)
```

## 밸런스 메모

`TUNING`의 적 체력 공식: `(hpBase + 웨이브×hpWave) × (1+hpGrowth)^웨이브`.
헤드리스 시뮬레이션(카드 무작위 선택, 집중 포격 가끔 사용, 10판씩 여러 묶음)에서 승률은 대략 20–80%로 묶음마다 크게 흔들렸고, 런 길이는 약 4–4.5분이었다.
집중 포격을 전혀 쓰지 않는 봇은 0/8로 졌다 → 탭 판단이 실제로 결과에 영향을 준다.
시너지 우선 선택 봇과 무작위 봇의 차이는 표본 안에서 뚜렷하지 않았다. 다음 튜닝 과제: 진화 보상 강화 또는 무작위 빌드 페널티.
